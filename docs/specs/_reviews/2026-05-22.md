# Spec corpus review — 2026-05-22

> Reviewer: claude-opus-4-7 (interactive session, pre-skill bootstrap)
> Corpus: `docs/specs/` (38 specs, ~8700 lines)
> Scope: full corpus
> This review was conducted before the `/specs` skill existed and seeded the skill's `anti-patterns.md` and `patterns.md`.

## TL;DR

Strong first attempt — top decile of solo-project spec corpora. The architecture (MAIN.md anchor, §-citation, source-file references, failure model hoisted, three-tier compatibility surface) is well-designed and the cross-spec citation web is dense and load-bearing. Biggest wins now are not adding more content but **owning the implementation-coupling honestly**, **marking stability tiers per spec**, **enforcing per-claim Why discipline**, and **separating drafts from normative specs**. Add a link-integrity validator to prevent rot.

## What's working

1. **Architecture of the corpus.** MAIN.md as a 7-section anchor (Frame → Failure Model → Perf → Stable Surface → Open → Sub-Spec Index → Cross-Refs), with sub-specs renumbering from §1.1, is a real spec layout — replicable, scannable, citable.

2. **Three-tier commitment ladder in MAIN.md §4 / §4.4 / §4.5** (stable core / compatibility cuts / out-of-scope) is unusual and load-bearing. Most spec corpora collapse these. → Promoted to skill `patterns.md` P-2.

3. **Cross-spec citation as primary connective tissue.** `[expression-gutter.md §3.4]` works because every spec renumbers from 1 and every entry is genuinely linkable.

4. **Hoisting cross-cutting contracts into MAIN.md** (failure model §2, perf targets §3) rather than scattering them. Sub-specs cite them by §-number.

5. **"This spec wins over implementation by intent" clause** (MAIN.md §7.13). Without it, specs rot into documentation; with it, they're enforceable.

6. **Honest open-question sections.** Almost every spec ends with `Open / Deferred`. `probes.md §2.1.1` "Future direction: runtime detection" is the gold standard.

7. **`(see src/...)` source-file pointers** turn the spec into a codebase index.

## Highest-leverage opportunities (now addressed by skill bootstrap)

### 1. "Implementation-agnostic" framing partly violated (now: frontmatter `layer` field)

MAIN.md said the spec is implementation-agnostic, but every sub-spec uses CodeMirror primitives normatively. **Fix shipped:** `layer: behavioural|binding|cross-cutting` frontmatter. Reviewer's `layer-leakage` validator flags drift.

### 2. Stability tier per spec (now: frontmatter `stability` field)

A reader couldn't tell at-a-glance whether `transport.md` was a stable contract or `state-identity.md` was aspirational. **Fix shipped:** mandatory `stability: stable|evolving|aspirational` frontmatter on all 38 specs.

### 3. Working-progress docs muddy the directory

`gamepad-handoff.md` and `gamepad-browser-test.md` are non-normative working docs but sit alphabetically beside authoritative specs. **Fix partial:** added `non-normative: true` frontmatter. **Open:** move to `_drafts/` next time the corpus is touched (recorded in MAP.md local conventions).

### 4. Add Why: discipline (now: skill template enforcement)

Strongest entries explained why; many didn't. **Fix shipped:** skill templates require `**Why:**` sub-lines on load-bearing claims; reviewer flags omissions.

### 5. Granularity inconsistent (themes.md 23 lines, radial-menu.md 867)

Different specs imply different uses of the corpus (axioms vs recreation-manual). MAIN.md framing implies recreation-manual target; by that bar `themes.md` is under-specified. **Open** — recommend choosing a convention before next major addition.

## Gaps in coverage (recommend adding sub-specs)

- **Clipboard model.** Referenced by structural-fuzzing.md but never defined.
- **Undo/redo semantics.** Many specs reference "pushes to undo stack" but none defines granularity / mode-crossing / live-edit interaction.
- **Time and clocks.** Currently scattered across transport, runtime-modes, visualisation, state-sync. The system has 4+ time sources.
- **Accessibility.** Mentioned once in keybindings.md (announcer); no screen-reader/motion-reduction/contrast spec.
- **Hardware↔WASM behavioural parity.** Named in MAIN.md §5.1 as open; a divergence table would prevent rot.
- **Compatibility-cut sunsets.** MAIN.md §4.4 entries lack target dates.
