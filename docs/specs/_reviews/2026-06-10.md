## TL;DR

The corpus's architecture is holding, but its **truthfulness is eroding in two specific ways**: (1) `stability: stable` claims that were never implemented (quantised eval, `?keymap`, console burst valve, modal queueing, WASM crash recovery, hardware-connect prompt), and (2) specs that didn't survive refactors (overlays.md cites 6 deleted files; gamepad.md never absorbed the eager-with-undo removal; input-dispatch §7 describes a fixed defect as current). Separately, the review surfaced a cluster of **real app defects where the spec wins** — including silent quantised-eval failure, comment destruction under structural editing, a dead A-button in the flagship gamepad mode, and a fully-built calibration feature with zero entry points.

## Part A — App defects the specs reveal (spec wins; ranked)

1. **Quantised eval is a silent no-op end-to-end** [code-evaluation.md §1.1/§1.11; wire-protocol.md §5.7]. `eval.quantised` → `sendJsonEval()` never includes a `quant` field (`src/transport/json-protocol.ts:469-484`); WASM path has no quant either. Firmware queue is specced+implemented; the editor never opts in. A performer choosing quantised eval gets immediate eval, mislabelled.
2. **Structural mutations destroy comments inside the affected form** [formatting.md §4.2; structural-editing.md §2.6/§2.10]. `treeFromLezer.ts:90-92` skips comments; `printTree.ts` has no comment handling; `applyOp.ts` reprints the whole top-level form. One slurp inside a commented form silently loses user text. Data loss.
3. **The A button is dead in the flagship gamepad mode** [gamepad.md §6.6.2]. `modal-shift.ts:90` binds `tap(A)` → `actOn.open`; `actOn.*` actions are registered but **no handlers exist** and no act-on transient layer exists. The verb-select scheme is ~25% implemented (grab quartet only).
4. **Calibration is fully built and completely unreachable** [calibration.md §2.1]. 513-line sequencer + 6 UI components + adapter exist; `mountCalibrationOverlay()` has zero callers; none of the three specced entry points exist. Spec calls it the "headline hardware feature demo moment". ~A day of wiring.
5. **Hardware-connect program-sync prompt doesn't exist** [runtime-modes.md §1.7]. Connecting hardware mid-session leaves device state silently divergent from the editor — the exact failure state-sync.md exists to mitigate, at the cheapest interception point.
6. **`?keymap` is a dead stable contract** [url-params.md §2; keybindings.md §1.13]. `profileFromUrl`/`profileToUrl` exported, zero callers; no import/export UI either.
7. **Keyboard users cannot open the main menu** [main-menu.md §2.1.2/§6]. L3+R3-only; no Escape binding, no arrow nav. (Menu is also half-skeleton: 4 of 8 root items.)
8. **Spurious atom-adjust on LB/RB press over a leaf atom** — knowingly shipped (`modal-shift.ts:181-189` documents the divergence); gamepad.md §6.7's held-modifier predicate is impossible with tap-on-press. Needs decision: accept+spec, or defer tap to release.
9. **Drift detection blind to physical outputs** [state-sync.md §1.2]. `driftDetector.ts:53` maps only `s1–s8`; every spec example uses `a1`/`d1`. As built, drift on voltage-driving outputs can never be detected. Real fix is a firmware streaming/mirroring decision.
10. **WASM crash recovery in `both` mode unimplemented** [MAIN.md §2.10, stable]. Worker port just rejects pending requests on error; no reinit path.
11. **Console burst valve unimplemented** [console.md §1.5, stable]. Typewriter at 20ms/char with no >3-pending flush → bursts visibly lag.
12. **Zen mode has no discoverable entry** [zen-mode.md §2.1–2.2]. Polished practice surface (exercises, hints, progress) reachable only by URL.
13. **Vis store can't honour the specced channel range** [code-evaluation.md §1.8 vs `visualisationStore.ts` hardcoded a1–a4/d1–d3; no s-channels]. Decide the supported set, state it once.

### Decisions needed (spec vs code both defensible)

- **Transport boot state**: spec says boots paused (transport.md §1.1); code boots `playing` and force-sends `(useq-play)` (`transport.machine.ts:28`, `appLifecycle.ts:99-106`). Instrument-boots-live vs DAW-boots-paused — one product decision, together with #5 above.
- **Probe restore semantics**: probes.md §1.5.5/§1.8.3 "never silently rebind" vs code's always-rebind-to-live-text (`probes.ts:1005-1050`). Code's behaviour arguably better for live editing; decide, then fix the other side.
- **Modal queue vs replace** [overlays.md §1.6]: code replaces. Queueing is probably over-spec; recommend spec→"replaces".
- **Help tabs**: user-guide.md "Resolved Decision #5" (3 tabs, Keybindings removed) contradicts help.md §1.1 + shipped code (4 tabs). Land it or strike it.

## Part D — Cross-cutting diagnoses (candidate ALIGNMENT.md entries)

1. **Stable-tier credibility**: ≥6 stable claims across the corpus are unimplemented. Either run a per-claim verification pass before granting `stable`, or the tier degrades to "intended".
2. **Built-but-unwired pattern**: calibration, zen entries, `?keymap`, act-on layer — implementation lands to spec, the final wiring/discoverability step doesn't. Cheap wins; also a process smell worth naming.
3. **PRD-shaped docs rot fastest**: user-guide.md and inspector.md are the most-drifted files and the two that aren't claim-structured. Convention: specs = numbered behavioural contracts; plans → `_drafts/`/ADRs.
4. **Aspirational content in present tense** (expression-gutter pulses, atom-manipulation widgets/settings, main-menu items): present-tense normative claims + Source-files entries for unbuilt code defeat the recreate-from-spec purpose. Mark unbuilt §s explicitly.
5. **State-sync is scaffolding without firmware**: layers 2–3 unimplemented, layer 1 sees only `s1–s8`. Needs a firmware streaming/snapshot decision before the feature can deliver.
6. **Settings tables aren't validated**: three specs list settings absent from `schema.ts`. A small test asserting spec-listed keys exist in the schema (or generating tables from it) kills the class.
