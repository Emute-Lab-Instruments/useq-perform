# v1.2.0 release scope — draft

Prepared 2026-09-08. This is a release-content and decision brief, not a second
task tracker. Durable execution remains in Ergon under
`work:daf710f6-3e37-4945-8c16-e953d80523a6`; existing related work is referenced
below. The [changelog](../../CHANGELOG.md) contains the proposed public copy.

**Proposed cut:** ship the structural editor, current hardware/browser control
runtime, visualisation and live controls; complete the already-approved
operator-modifier migration; include only the existing limited browser-audio
surface. Defer calibration, the larger synth library/editor, full state
restoration, and new query/graphics experiences. These are recommendations for
the release discussion, not newly accepted implementation commitments.

## Unfinished features and proposed decisions

| Feature | What is unfinished | Recommendation for v1.2.0 |
| --- | --- | --- |
| **Operator modifiers and qualified names** | Specs require attached blocks such as `sin[uni]` and exact `/` binding identity. Compiler and editor still implement older slash adapters; the generated reference has the older schema. | **Finish before release.** Treat compiler, inventory, editor affordances, formatting, witnesses and migration guide as one change. An explicit contract deferral is the alternative; shipping contradictory examples is not. |
| **Language/reference/firmware coherence** | Recorded pin is older than current reference metadata; newer checkout has three failing stateful-waveform corpus cases and still lacks attached modifiers. | **Release gate.** Select one reviewed firmware revision and rebuild interpreter, NodeDef, reference and manifests from it. Do not fix stale expectations without positive semantic checks. |
| **CV 1V/oct calibration** | Editor sequencer and screens exist; firmware takeover, calibration state and flash persistence are absent. `calibrate-*` returns `success:false`. | **Defer.** Keep it out of shipped-feature copy and ensure unavailable controls explain or prevent unsupported use. Completing it instead requires backend and physical voltage validation. See [calibration §1.6](../specs/calibration.md). |
| **Full synth library / voices** | Current registry is `osc/sine` only, with `voiceFanout:false`; filters, VCA, noise, delay, richer voices and their DSP evidence remain future work. | **Defer expansion.** Ship a bounded browser-audio feature or explicitly label it experimental. Do not promise a complete modular synth library. |
| **Synth editor integration** | Planned node rails, ghost parameters, param scopes/widgets, graph overview and identity feedback in [synthesis §§7.2–7.6](../specs/synthesis.md) are not implemented as those surfaces. | **Defer.** Existing engine indicator and source evaluation can ship independently. |
| **Complete state sync / restoration** | Drift scoring is limited to `s1–s8`; snapshot apply skips cell restoration and patches state slots by position. Worker replacement re-evaluates current editor text, which may differ from the last accepted program. | **Defer the full-restoration promise.** Require truthful degradation and recovery tests for shipped behavior, especially invalid edited text and audio producer loss. See [state sync](../specs/state-sync.md). |
| **Remaining gamepad actions** | Eager-with-undo is deferred; `actOn.duplicateDrop` currently ends grab rather than implementing true duplicate-drop. | **Defer these actions or implement them before advertising them.** Existing navigation/radial/edit flows need a real-controller pass. |
| **Temporal queries / askable signals** | `q/zeros`, `q/crossings`, `q/range`, `q/explain` exist in newer host/WASM source, beyond the parent pin. Supported fragment and capacities are bounded; integration, oracle/law evidence and the query overlay remain incomplete. | **Keep out of the default v1.2.0 promise.** A separately identified experimental host/WASM feature is possible after promotion/validation; firmware and general event extraction are excluded. See [temporal queries](../../src-useq/docs/specs/temporal-queries.md). |
| **Firmware beta cutover** | Exact production rollback archive, published artifacts and physical legacy/beta update journeys are not established by this audit. | **Release acceptance work**, not a new feature implementation. Publish only after the existing cutover procedure passes for supported targets. |
| **Target headroom / expander electrical behavior** | Static builds and native tests do not establish target stack/heap watermarks, Wire behavior or voltages on silicon. | **Gate each advertised hardware profile.** A full-profile/parity claim must wait for matching evidence; a profile lacking acceptance may be excluded from this release. See [runtime alignment](../../src-useq/ALIGNMENT.md). |
| **Engine Ledger / The Machine expansion** | In-app witness runner handles `eval`/`sample`, not all diagnostic/tick/health/config/clear cases; some Ledger links and deeper schematic/navigation surfaces are deferred. | **Ship current M1 surfaces with honest limits.** Ledger stays developer-only; no claim of complete clause coverage. |
| **Hydra / NISPS and other extensions** | Hydra has a separate tracked implementation context; NISPS is a separate runtime integration, not established by this editor pin. | **Separate release scope.** No implied inclusion through shared ModuLisp ancestry. |

The source-approved modifier direction already supersedes the older
adapter-namespace plan. The pending question is whether completion is required
for this release, not whether the earlier namespace implementation was ever
done. Browser-audio scope and calibration inclusion are also awaiting the
operator's release preference; until answered, the recommendations above remain
proposals.

Explicitly outside this default scope: firmware MIDI/MIDI output, firmware
audio synthesis, firmware temporal analysis, audio input/recording/sample
playback, user-authored browser DSP, graphical cable editing, new scheduling
semantics, nonnumeric signal roots, and general cross-target bit identity.
Grammar Lab and Storybook are research/development surfaces, not new production
editor modes.

## Evidence and acceptance

This pass refreshed Git refs, inspected current source/specs and live Ergon,
and re-ran a small eval probe against the retained clean newer-runtime WASM
candidate. Arithmetic and `(lfo/saw ...)` succeeded; `(saw[lfo] ...)` failed
with `undefinedName`/`type` diagnostics. This directly confirms the syntax gap
for that retained artifact; it is not a new full build or a browser result.

The [September 6 clean-candidate comparison](../reports/architecture-review-2026-09-06.md)
is retained historical evidence, not a fresh result for today's dirty tree:

| Recorded candidate | Results relevant to this release decision |
| --- | --- |
| Firmware pin `3f73fcc` | Full build/provenance passed; WASM conformance 85/85; two app reference-data failures because the older inventory lacks newer metadata. |
| Newer `02299d2` | Full build/provenance passed; WASM conformance 82/85; one app witness failure. Bare-`saw` stateful fixtures disagree with newer semantics, and attached syntax still fails. |
| Physical/browser limits | That comparison did not execute browser journeys, device flashing, electrical checks, listening or production cutover. |

Candidate acceptance should establish the following on the **same selected
source/artifact pair**, with explicit supported hardware targets:

1. Coherent source pin, generated assets/reference and compiler manifests;
   production and test typechecks, lint/docs, structural/unit and native/WASM
   conformance, with existing failures resolved rather than hidden.
2. Full browser journeys plus `npm run test:release`, including the current
   Chromium Worker-eval check. `test:release` alone is not the native C++,
   full Playwright, firmware-build or physical-acceptance suite.
3. Edit → evaluate → see/hear output; bad edit preserves the accepted result;
   disconnect/crash/recovery; save/reload/undo identity; visualisation,
   live-edit/MIDI, real gamepad and supported hardware bindings.
4. Physical listening for browser audio, and exact-target resource/I/O,
   protocol and updater observations for hardware. Use the existing
   [listening guide](../synthesis/LISTENING_GUIDE.md) and
   [firmware update procedure](../testing/firmware-update-local.md).
5. If publishing the migration: retain the deployed editor at `/legacy/`,
   validate legacy and beta devices, then follow the existing publication
   order. No deployment or firmware promotion is authorized by this draft.
